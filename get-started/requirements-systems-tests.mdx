Flow becomes useful after you connect items. In this guide, you build one short thread: a system, what the system must achieve, and the evidence that shows how close it is. The same procedure applies to all structures that your team models, for example interfaces, parts, analyses, or risks.

You must have permission to edit the current branch. The data model must have the categories that you will use. Category and field names depend on your project. If the current branch is protected, [create a branch](/get-started/creating-a-branch) first.

## 1. Create a system and give it an owner

In a Table view, focus the parent system. Type a name in the bottom row. This row shows **New** and the category name, for example *New System...*. Press Enter. Flow puts the new item below the focused item.

If more than one category is possible at that position, use the type button of the row to choose one. To use the full form, select the **New** button of the view, for example **New System**.

If the view has a filter on a tag or person field, for example Status or Owner, the new item gets those filter values. Thus, the new item stays in the view where you created it.

Open the new item. Describe its boundary: what is inside the item and what it connects to.

Set the **Owner** to the engineer closest to that part of the design. This engineer is the best person to keep the item up to date.

## 2. Record what it must achieve

Add the item that states the intent. Your model sets the type of this item: a design target, a budget, an interface definition, or a requirement. Put measurable values in number fields and also in the text. Then Flow can compare these values with results later.

## 3. Connect it

Connect the new item to the system that delivers it. Also connect the new item to the items that it comes from, for example a higher-level target. These links answer two questions that all engineers ask: where is this item delivered, and why does it exist?

Check each relationship from the two sides. The type and direction of a link give its meaning. If two items are only near each other in a table, they are not connected. If the necessary relationship is not available, ask your Admin to check the data model.

## 4. Record the evidence

Add the item that shows if the intent is met, for example a test case or an analysis. Connect this item. In the details panel of an item, a linked-items tab has the same bottom row as the Table. An example of this tab is **Test Cases**. Type a name in this row. Then press Enter to create an item that is already linked.

Record each result as a separate item with the measured value, date, and conditions. Attach the report to the item. Keep results separate. Do not overwrite one value.

For example, a vehicle team has a drag coefficient target of 0.28. The team records three prototype builds at 0.296, 0.287, and 0.279. Only the last result meets the target. If the team keeps all three results, the results show the trend toward the target.

## Check the thread

Start at the system. Follow the thread to what the system must achieve, who owns it, and the latest evidence. Then start from a result. Follow the thread back to the system.

To choose the fields that the details panel shows for a category, open the **Options** menu of the panel. Choose **Configure Fields Visibility...**. Hidden fields are available under **Show more**.

If another engineer can follow the thread without help from you, the thread is complete. [The systems graph](/core-concepts/the-systems-graph) explains why the thread is important. [Getting data into Flow](/get-started/getting-data-into-flow) shows how to add the records that you have now.
