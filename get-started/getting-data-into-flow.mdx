Most programs already keep their engineering information in other locations: spreadsheets, specifications, review decks, models, and issue trackers. Choose the route for each source. Before you add all your data, start with a small sample.

## Choose the route

| Source | Route | Check |
| --- | --- | --- |
| A few records | Create and edit items directly | Category, fields, owner, links |
| A spreadsheet | **Import from → CSV/Excel** | How columns map to fields, how rows match items, relationships, validation |
| Another Flow project | **New project** from that project, with **Items** checked | What Flow copied and what it did not copy; refer to [Starting a project](/get-started/starting-a-project) |
| A document, deck, or image | Ask the agent to extract the data | Each candidate against its source, and how it maps to your model |
| A connected tool | The workflow of that integration | Access scope, and if the integration reads, imports, or writes |
| Your own scripts or AI clients | The [Customer API](/api/examples/batch-writes) or [Flow MCP](/api/mcp/overview) | Authentication, branch, and permissions |

## Import a spreadsheet

1. Open the project and branch.
2. Open a view of the records that you will import.
3. Choose **More actions → Import from → CSV/Excel**.
4. Upload the file. If the workbook has more than one sheet, choose the sheet to import under **Sheet**.
5. Under **Item type**, choose if all rows become one category or if a column sets the category of each row.
6. For each category, map columns to fields and relationships. These include names, descriptions, values and units, owners, and the parent of each row.
7. Set **Match items by** so that rows update items that already exist and do not make duplicates.
8. Under **Destination**, choose the location for items that have no parent in the file. Choose **Project root**, **Link to an item**, or **File links only**. **Link to an item** puts these items under an item that you select. **File links only** writes only the link columns of the file.
9. Under **Review**, check the validation and the proposed changes.

A relationship column must always refer to the related item in the same way. If a value matches more than one item, correct the problem before you continue. If the same source row occurs two times with different values, correct the problem before you continue.

**Requires you to act:** Correct the validation problems that block the import. Then choose **Import to new branch**. The import goes into its own branch. Thus, you can examine the import before it goes into the shared work.

For other formats, for example ReqIF, SysML, Word, and PDF, refer to [Importing and exporting](/importing-exporting/csv).

## Extract from a document

The agent can make candidate records from a document. Give the agent a task with clear limits. Tell it the source, the item types that you want, and where they go. Also tell it what to keep, and if you want analysis or changes.

For example, attach a design review deck. Ask the agent for the targets in the deck. Ask it to put each target under its system and to record the slide that each target came from.

If your team has [skills](/ai-automations/skills) for how to write items, the agent uses these skills. Thus, the results follow the rules of your team.

Extraction and creation are separate steps. Compare each candidate with its source. Examine values from tables, charts, or diagrams very carefully.

## Use connected tools deliberately

With an integration, Flow can read information and not create a Flow record for it. Other integration actions create or update records in Flow or in the connected tool. Flow branches [do not include](/core-concepts/branching#keep-the-context-visible) the connected tool. Before you use a connection, make sure that you know what it does. [Integrations](/integrations/integrations-list) shows what each integration supports.

You can also ask the agent to connect, change, or disconnect an integration. The agent shows the same connection form or sign-in on a card. It proposes changes, for example write-back. You confirm these changes with your own permissions. You enter credentials in the card, never in the conversation.

## Check what arrived

Open some of the new records. Check names, values, units, and owners. Follow their relationships. For an update, make sure that the correct records changed. Make sure that there are no duplicates.

Then continue with [Creating a branch](/get-started/creating-a-branch).
