Before you create a project, check if your team already has a project. Keep related work in the same project, so that its items can connect.

You must have administrative access to create a project. If **New project** is not available, ask your Admin.

## Choose a starting point

Open the project switcher. Choose **New project**. Enter a **Name**. In **Start from**, choose one of these options:

| Start from | What you get | Use it when |
| --- | --- | --- |
| **Default template** | The data model, saved views, and dashboards that your organization configured | Your organization already has a structure that it uses |
| **Blank project** | An empty model with only the built-in Diagram category | You define a completely new workflow |
| An existing project | The parts of that project that you select, and its items if you select them | You start a program that is similar to a current program, or you start from a design that you have now |

When you start from an existing project, **What to import** shows **Data model**, **Items**, **Views**, **Automations**, and **Skills**. At the start, all options except **Items** are checked. Views and items depend on the data model. If you clear **Data model**, Flow also clears the views and items.

**Items** copies the current items of the source project from Base. Each copy is a new item with its own number. The copy has the same category, field values, and formulas as the source item. The copy also has the links to the other copied items.

The history of the copy starts in the new project. Flow does not copy branches, past history, comments, files in file fields, or pins on links. If the source has more than 50,000 items, Flow cannot copy its items, and the dialog tells you this.

**Requires you to act:** Check the name, the starting point, and the selected parts. Then choose **Create**.

The project opens immediately. Flow copies the items in the background. While Flow copies the items, it shows the percentage that is complete. After all the items are in the project, Flow adds the copied automations.

## Agree the model before adding data

Open the new project. Look at its categories. Before the team enters many records, agree on these four things:

- Which categories contain your structures: for example, systems, interfaces, requirements, analyses, tests, parts, or other structures that your program records.
- Which fields contain the values that you compare, and where Flow records the owner of each item.
- Which relationships connect an item to its system and to the evidence that supports it.
- Where to put results and the files that support them.

A template gives answers to most of these questions. In a blank project, you must answer them first. An Admin can configure the categories and fields. [The data model](/core-concepts/the-data-model) explains the ideas behind that configuration.

## Open a view for your first task

Choose a saved view that shows the data for your task. A systems view starts from the product breakdown. A table shows names, owners, and values next to each other, and it is the fastest way to check them.

If the project has no saved views, agree on one first view with your Admin. Improve the view as the model becomes larger.

## Check your working context

Before you create or change anything, make sure that the sidebar shows the correct project and branch. Your role and the permissions of the branch control which actions you can do.

You are ready when you can name the project, identify the categories that you will use, and open a view of them. Continue with [Connecting your first items](/get-started/requirements-systems-tests).
