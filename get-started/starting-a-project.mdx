A project holds one program's engineering model, saved views, and working information. For the example in these guides, that program is the electric vehicle.

Before you create a project, check whether your team already has one. Related work belongs in the same project so its requirements, systems, and tests can connect.

Creating a project requires administrative access. If **New project** is unavailable, ask your Admin.

## Choose a starting point

Open the project switcher and choose **New project**. Enter a **Name**, then choose **Start from**:

| Start from | What you get | Use it when |
| --- | --- | --- |
| **Default template** | Your organization's configured data model, saved views, and dashboards | Your organization has an established structure |
| **Blank project** | An empty model with only the built-in Diagram category | You are defining a new workflow from scratch |
| An existing project | The parts of that project you select | You are starting a program like one you already run |

When you start from an existing project, **What to import** lets you choose **Data model**, **Views**, **Automations**, and **Skills**. Views depend on the data model, so selecting views also selects the model. Copying configuration does not copy the source project's working history.

**Requires you to act:** Check the name, the starting point, and the selected parts, then create the project.

## Agree the model before adding data

Open the new project and look at its categories. Before the team enters many records, agree on four things:

- Which category holds systems such as **Battery System**, and where each system's owner is recorded.
- Which fields hold a requirement's statement, target value, unit, and state.
- Which relationships connect a requirement to the system that delivers it and the test that verifies it.
- Where test results and supporting files belong.

A template answers most of these for you. A blank project needs them answered first; an Admin can configure the categories and fields. [The data model](/core-concepts/the-data-model) explains the ideas behind that configuration.

## Open a view for your first task

Choose a saved view that shows what you need. A **Systems** view starts from the product breakdown. A table is the fastest way to check names, owners, and values side by side.

If the project has no saved views yet, agree one starting view with your Admin. Refine it as the model grows.

## Check your working context

Before you create or change anything, confirm the current project and branch in the sidebar. Your role and the branch's permissions decide which actions you can take.

You are ready when you can name the project, recognize the categories you need, and open a view of them. Continue with [Requirements, systems, tests](/get-started/requirements-systems-tests).
