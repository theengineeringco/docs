ReqIF is an interchange format many engineering tools read and write. Despite its name, it carries any structured objects with attributes and links. Flow exports any item types you map, with their attributes, hierarchy, and links, and imports ReqIF documents into a new branch.

Anyone who can see the data can export it. Importing requires editing access; read-only and external users cannot import.

## Export

<VisualPlaceholder kind="Screenshot" title="ReqIF export mappings">
  The ReqIF export Mappings step: each Flow type mapped to a ReqIF type name with its fields and item counts, Spec object ID and Spec hierarchy ID marked, and the preset bar at the top.
</VisualPlaceholder>

1. Choose **More actions → Export as → ReqIF**.
2. Select **Add scope** for each part of the project to export. A scope pairs a root item with a saved view, and can be filtered. Then select **Continue to mappings**.
3. For each Flow type, set the exported ReqIF type name and choose which fields to include, with their attribute names and datatypes. For tag fields, edit the exported enumeration values; leave a value blank to exclude it.
4. Set **Spec object ID** for each item's identity and **Spec hierarchy ID** for its place in the hierarchy. Each can be auto-generated, the Flow ID, or a Flow field, with an optional suffix. Match your exchange partner's convention.
5. Check the summary of scopes, items, and types, then select **Download .reqifz**.

Excluding a type moves its children up to the next included level. A filtered export keeps the parents of matching items, so the hierarchy matches Flow. The `.reqifz` archive includes embedded files.

To reuse a mapping, save it as a preset. Presets belong to the project. After changing a preset's mapping, select **Update** to save it.

## Import

<VisualPlaceholder kind="Screenshot" title="ReqIF import destination">
  The full-page Import ReqIF Destination step: the starting branch, the new branch name, Top-level items set to Under an item with an item chosen, and Link directions listing Specification hierarchy and one other link type set to Downstream. Back and Continue sit in the bar at the bottom.
</VisualPlaceholder>

1. Choose **More actions → Import from → ReqIF** and drop or upload a `.reqif` or `.reqifz` file.
2. On **Item types**, choose the Flow item type each ReqIF type becomes. Objects of unmapped types are skipped; the import does not add types to your data model. Apply a saved preset here, or select **Save preset** to reuse the whole configuration.
3. On each type's step, map attributes to fields and enumeration values to options, and choose how objects match existing items with **Flow ID from** and **Match Flow entity by**.
4. Under **Destination**, choose the branch to start from, name the new branch, and place the **Top-level items** at the **Project root** or **Under an item**.
5. Under **Link directions**, set each link type to **Downstream**, **Upstream**, **Cross-link**, or **Skip**.
6. Check **Review**, which previews the items the import will create and update, with counts per type. Nothing is written until you select **Create branch & import**.
7. After the import, select **Open branch** and check the hierarchy, values, and links.

The import lands on its own branch, so every imported value is traceable and reviewable before it merges; see [Branching](/core-concepts/branching). When a re-imported object has no value for a mapped attribute, Flow clears that field rather than keeping the old value.

Before a full handoff, exchange a small sample that includes nesting, enumerations, links, and an embedded image, and open it in the receiving tool.
