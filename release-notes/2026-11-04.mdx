## New diagram editor

Diagrams, the Architecture tab, embedded diagram previews, diagram exports, and AI diagram previews now use Flow's own diagram editor. Existing diagrams open as before, with no watermark on any domain. Every shape, including frames and horizontal and vertical swimlanes, comes from the canvas toolbar's shape picker, which adds a chevron for process-step flows. Shapes also gain a solid fill in the full shape color, and draw.io Step shapes import as chevrons.

The toolbar's Entity picker adds several items at once. Tick each item, then press **Add** to place a card for every one without overlap, and undo them together in one step. A selected wire shows only its end handles until you point at a run or bend, and you can drag a run from anywhere along it. Dragged runs and bends snap to ports, connected shapes, and the wire's other runs, and hand-routed wires follow the shapes they connect when those shapes move. Turn off the moving highlight on selected wires with **Animate wires** in the diagram menu.

## Side-by-side review of AI Word edits

When Flow AI edits a Word document, the edit card shows the original and edited documents as thumbnails, with removed text in red and added text in green. Click the card to open both documents side by side as pages.

## Improvements & Fixes

### Agent

- **Mode menu.** The composer's Mode menu holds Ask first, Auto-accept, and, for project admins, Super user, replacing the separate Standard / Super user chip. Super user lets the agent make every change in that chat without asking, admin changes included.
- **Super user approval.** The request to turn on super user mode shows what the agent will do and a short list of the admin changes at a glance. The reason is one click away.
- **Saved views from chat.** Asking Flow AI to create or change a view can set its table columns, filters, and sort in the same step, checked against the project's data model.
- **Update several branches from their parents.** The chat shows one card with a row per branch and one **Update all** button. A branch with conflicts shows them in its row, and you apply it on its own.
- **Agent changes appear live.** Branches, reviews, branch checks, files, findings, memories, and item history that the agent changes show while the chat runs, without a page reload.
- **Messages sent after Confirm.** When you confirm an action and send a message before it runs, the chat records that the action did not run, and the next reply no longer fails with an error.

### Formulas

- **Bulk edits.** Creating or updating several items at once spends less time updating dependent formulas.

### Integrations

- **Slack threads.** Flow follows the threads it was mentioned in or started, so replies reach the conversation without mentioning @Flow again. Flow answers only when a reply is meant for it. _(requires configuration)_ Existing Slack apps need the `message.channels` and `message.groups` bot events added under Event Subscriptions. Until then, replies still need to mention @Flow.

### Views

- **Top level of views.** A view's top level shows only its start type. An item of a type the view nests, such as a requirement in a systems view, appears under its parents and no longer also at the top level. Creating an item the view won't show now works instead of being refused, and the create form notes which upstream item it needs to appear there.

## API Changes

- **Saved view columns, filters, and sort.** Creating or updating a shared saved view through the Customer API or the [MCP server](/api/mcp/tools) can set its table columns, filters, and sort in the same call. Flow checks them against the project's data model and refuses a filter that names an unknown field, option, or type, saving nothing.
