A comparison shows the differences between two states of the project. These states can be two branches, a branch and one of its baselines, or two points in the history of one branch. A comparison does not apply changes. A comparison between two branches shows the differences from the histories of the two branches. To see only the changes that a branch will merge, open the review of that branch.

## Choose the two sides

1. Open the actions menu of the branch selector, or the menu of a branch row.
2. Choose **Compare with...**.
3. On each side, select a **Branch** and a **Point**. At first, the **Point** list shows **Current** and the baselines of the branch.
4. To start from one change instead, choose **Changes up to …** on one side. Then select a change. The list shows the newest change first, and you can search the changes.
5. Put the start state on the left side and the result state on the right side.
6. Open **Compare changes**.
7. Select an item to see its changed fields and relationships.

<Illustration name="comparing-what-a-comparison-includes" width={600} alt="A proposal made changes A and B; Base has since made change C. The proposal's review shows only A and B, what would merge. Comparing the two branches now also shows C." />

A comparison of **Base** at the last change before the proposal branched with **Proposal** at **Current** shows changes A and B. To select that point on **Base**, choose **Changes up to …**. A comparison of **Base** at **Current** with **Proposal** at **Current** also shows change C, from the other side. To see only the changes that the proposal will merge, open its review. These changes are A and B.

Use the swap control to reverse the two sides. Filters and display options limit the list. To see all the differences, clear the filters and display options.

To compare one item, open the item menu. Then choose **Compare with branch...**. The **Point** list shows the same types of points, but it shows only the changes to that item.

**Overview** shows information about the point on the right side. For a baseline, it shows who created the baseline and when. For a merged branch, it shows who merged the branch. It also shows the discussion for that point.

Baselines do not change. If a side shows **Current**, that side changes when the branch changes. If Flow tells you that the comparison is expired, choose **Reload comparison**. To mark a state that you can open again later, see [Baselining](/branching/baselining).

## See differences in a view

You can also see the differences in a branch from a table.

- In **Display options**, set **Show changed in branch** to on. A changed value shows above its previous value. Flow puts a tag on each item that is created, updated, or reordered. Tree and Reader mark changed items. This option is not available on Base.
- In **Choose columns...**, choose **Add field**. Then choose **Field in another branch…**. Select a branch and a field. For each row, the read-only column shows the value of that field in the other branch. If the other branch does not contain an item, the column shows "Not in" and the name of that branch. When you switch branches, the column continues to show its branch. Flow saves the column with the view.

## Access

Viewers can open comparisons. External recipients can compare only the current state of the branches that are shared with them. They can see only the items and fields that their share shows. Points in history and **Overview** are not available to them.

When you choose a side, Flow does not switch the branch that you work in. Before you edit again, check the branch selector.
