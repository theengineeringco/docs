Integrations are how Flow pulls and manages context from the places work already happens: code, tickets, chat, documents, CAD, and test data. That context sits beside your systems in Flow, so people and agents can see what you intend to build and how close you are. The same connections are how agents reach those tools to act.

## See what is connected

Open **Settings → Administration → Integrations**. The list shows only the integrations your deployment offers, and **Search integrations** filters it. Each row shows its status: **Connected**, **Not connected**, or, where each person connects their own account, **Your account: not connected**.

## Set up from the agent

You can also ask the agent to connect, change, or disconnect an integration, for example "Connect Slack and let the Battery System project use it."

1. The agent shows a card with the integration's own sign-in or connection form. Credentials go into the card and never pass through the conversation.
2. For changes such as turning on write-back or choosing projects and channels, the agent proposes each change as a row. Untick anything you don't want and select **Apply**.
3. The changes run with your own permissions, so workspace-wide changes need an Admin.

## Connect your own tools

**Custom MCP** connects an MCP server you run to Flow's AI. An Admin with access to all projects adds the server under **Settings → Administration → Integrations → Custom MCP**, chooses its **Allowed tools**, and turns on **Enabled**. New connections start disabled.

To reach Flow from your own code or AI clients, use the [customer API](/api/quickstart) or [Flow MCP](/api/mcp/overview). Both act with the connected user's permissions.

## Limits

- What an agent can do depends on the deployment, administrator settings, the connected account, and that tool's own permissions.
- Writes to an external tool happen immediately. Flow branches record changes in Flow, not in other tools; see [Branching](/core-concepts/branching).
- Check a new connection with a narrow read before turning on writes, and review what agents sent in [Activity](/ai-automations/activity).
