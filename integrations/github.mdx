Connect GitHub to let Flow AI read repository content, inspect pull requests, and run project automations. One Flow workspace can connect multiple organizations using the same GitHub server and App.

## What you can do

| Capability | How it works |
| --- | --- |
| Browse repository context | With **GitHub Repo Browsing**, list connected repositories, browse directories, find files by name or path, and read file contents at a chosen ref. |
| Inspect pull requests | Read a pull request's description, author, branches, merged status, changed files, and patches. Compare the change with requirements and tests in Flow. |
| Propose a code or documentation change | With **GitHub Writeback**, create a new branch, create or update files, and open a draft pull request. This does not merge the change or delete files. |
| Run pull request reviews | Enable **Review pull requests** for a repository in the current Flow project and configure the review automation's instructions. |
| Choose automatic or requested reviews | Enable **Auto-review** for automatic review events. With it off, request a review through an `@flow` mention. |
| Follow up after a merge | Use a GitHub pull-request-merged trigger for repositories enabled in the project. This does not require Auto-review or an `@flow` mention. |

<Note>
  With repository browsing enabled, the repositories granted to the connection are available across all projects in the Flow workspace. Project repository settings control automation; they do not restrict read access.
</Note>

## Try it with Flow AI

- “Read this pull request's changed files and patches. Compare the implementation with the linked interface requirements in Flow, citing the files behind each finding.”
- “Find the configuration files in this repository and explain how their limits compare with the limits defined in Flow.”
- With write-back: “Update this repository's interface documentation to match the reviewed Flow requirements. Open a draft pull request and include the requirement references in its description.”

## Automation ideas

Define the review criteria and output in a project automation. Connecting the App and enabling a repository do not supply those instructions for you.

Automatic reviews require **Auto-review**; with it off, use an `@flow` mention for an enabled repository. Merge-triggered work is separate and does not require Auto-review. Configure triggers through [Automations](/api/automations/overview). If the workflow also posts to [Slack](/integrations/slack) or opens a [Jira issue](/integrations/jira), configure that connection and its write-back permissions too. Opening a draft PR does not approve or merge it.

### Review code against requirements

**Trigger:** GitHub pull request review event.

Read the PR changes and the Flow requirements they reference. Report mismatches, missing tests, and evidence you could not inspect. Return a review outcome using explicit criteria. Requires project repository review access and browsing for additional file reads.

### Documentation impact after merge

**Trigger:** GitHub pull request merged.

Inspect the merged change and identify affected Flow interfaces or requirements. Return a follow-up summary with the PR link and affected items; enable updates only if the automation is meant to change them.

### Repository documentation refresh

**Trigger:** Manual run or schedule.

Compare a named documentation file with selected Flow items. If they differ, create the agreed file updates on a new branch and open a draft PR. Requires GitHub write-back; record the PR link to avoid duplicate proposals.

## Before you start

You need a Flow admin who can manage the workspace connection and permission to install or approve a GitHub App in the target organization. For organizations with SSO, sign in through the organization's SSO before installing the App.

Use the managed Flow GitHub App when that option is available. Choose a dedicated App for GitHub Enterprise Server or an organization that requires its own App. GHE.com is a separate Enterprise Cloud option in dedicated-App setup.

Flow's dedicated-App setup requests read and write permissions for contents, pull requests, issues, and checks, plus read permission for metadata. Review the permissions and repository selection on GitHub before approving.

## Enable browsing and automation

**Requires you to act:** Enable **GitHub Repo Browsing** to let Flow AI read connected repositories. Enable **GitHub Writeback** only when you want it to create branches, edit files, or open pull requests.

{/* ![Configure GitHub browsing and writeback](images/github-access.png "human-intervention: enable GitHub capabilities") */}

**Requires you to act:** Under **Pull request automation**, check the current Flow project, find a repository, and enable **Review pull requests**. Enable **Auto-review** if reviews should run without an `@flow` mention. Configure the work to run in the project's automations.

{/* ![Configure project pull request automation](images/github-automation.png "human-intervention: enable project pull request automation") */}

Changes made in GitHub take effect directly. Reverting a Flow branch does not undo a GitHub action.

## Verify the connection

Confirm the organization appears under **Workspace access** with a connected status. With browsing enabled, ask Flow AI to read a known file or pull request in a granted repository.

For automation, use a test pull request in a repository enabled for the current project. Mention `@flow` and inspect the resulting automation run. A successful repository read does not verify webhook delivery.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The installation is waiting for approval">
    Have a GitHub organization owner approve the App. Return to Flow and enter the installation ID manually if the browser did not complete the return flow. Review access and select **Connect organization**.
  </Accordion>
  <Accordion title="A repository is missing">
    Check its organization's App installation and repository grants in GitHub, then refresh the connection in Flow. If one organization fails to load, other organizations can still return repositories; check the reported error before treating the list as complete.
  </Accordion>
  <Accordion title="The agent cannot browse, even though automation is configured">
    Enable **GitHub Repo Browsing**. Project review settings do not enable browsing. Also check that Flow AI is enabled and that the repository belongs to a connected installation.
  </Accordion>
  <Accordion title="An inline @flow mention does not trigger a review">
    Check project repository settings and the automation trigger. Existing dedicated Apps need the appropriate pull request review comment event subscription in GitHub; newer Apps include it during setup.
  </Accordion>
  <Accordion title="You need another organization or a different GitHub server">
    Use **Add organization** for another installation of the same App on the same server. Replacing the App or server requires disconnecting every existing installation first.
  </Accordion>
</AccordionGroup>

## Disconnect an organization

**Requires you to act:** Use the disconnect control for the organization under **Workspace access**. This removes its access across all Flow projects. Saved project automation settings remain and resume when that organization is reconnected.

{/* ![Disconnect a GitHub organization](images/github-disconnect.png "human-intervention: disconnect a GitHub organization") */}

Disconnecting in Flow does not delete repositories or uninstall the App from GitHub. Manage the App's installation in GitHub when you also want to remove its GitHub-side access.
