Every request targets an environment and a tenant. Project-scoped endpoints also require a project ID.

## Choose your environment

| Environment | API base URL |
| --- | --- |
| Production | `https://backend.branch.flowengineering.com` |
| RVT | `https://backend.rvtech.branch.flowengineering.com` |
| Rivian | `https://backend.rivian.branch.flowengineering.com` |

Use the environment assigned to your workspace. For another hosted or self-hosted deployment, use its own API origin.

The **API URL** in **Settings → API & MCP** points to Swagger at `/customer-api`. Remove that suffix when constructing requests. Do not add an extra `/api` prefix.

## Select your tenant

Pass the tenant identifier in the `customer` header:

```http
X-API-Key: brd_your_api_key
customer: your-tenant
```

You can find the tenant identifier at the end of the **MCP URL** in the same settings page: `https://your-api-host/mcp/your-tenant`. Use only the final tenant segment as the header value. Do not send requests to the MCP URL when using this REST API.

A tenant identifier selects a workspace. It does not grant access. Your key must belong to that tenant on the selected environment.

## Select your project

Use the project's ID in paths such as `/project/{projectId}/entities`. Retrieve accessible projects with `GET /project`, or use the **Project ID** shown in API settings. Use the ID rather than the project's display name or URL slug.

## Shared API, workspace-specific data

The reference describes the shared customer API. Categories, custom fields, and their IDs belong to your workspace: discover them through the data model endpoints before writing values. Permissions and configured features can also affect which operations succeed.

Deployments can temporarily run different releases. The Swagger document at your environment's `/customer-api` URL describes that deployment. Consult the existing [release notes](/release-notes) for API changes.
