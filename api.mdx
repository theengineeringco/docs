## Start agent chats

Use `POST /ai/agents` with `project_id` and an optional opening `messages` array to create a chat. Chats are private to the key owner by default; set `visibility` to `shared` only when the workspace should see them. When you provide opening messages, the default `wait: false` returns while the agent works. Without messages, the chat starts idle. Read `GET /ai/agents/{id}` for its transcript and status, then use `POST /ai/agents/{id}/messages` to start or continue it. The [endpoint reference](/api/reference) describes the full request bodies.

`POST /ai/agents/{id}/messages` returns `job_id`, `queued`, and `duplicate`. With `queued: false`, the turn has started. Poll `GET /ai/trigger/runs?agent_ids={id}` until the run is not `running`, then read `GET /ai/agents/{id}`. With `queued: true`, an earlier turn is still running and the message waits for it to end. Poll `GET /ai/agents/{id}` until the reply is in the transcript. With `duplicate: true`, this exact send already happened and `job_id` is the original send.

To have a running turn read a queued message at its next step, send [`PATCH /ai/agents/{id}/messages/{jobId}`](/api/endpoints/patch-ai-agents-id-messages-jobid) with `delivery` set to `live`. This applies only when the running turn is yours (same person and role). Otherwise the message keeps waiting. `eventually` is the default. A message that moves the chat to another branch cannot be `live` and returns `400`. A message that has already started a turn is left as it is.

## Check whether a branch can merge

Use [`GET /project/{projectId}/branch/{id}/merge-readiness`](/api/endpoints/get-project-projectid-branch-id-merge-readiness) before you merge a branch. The response lists every gate that blocks the merge in `blockers`, not only the first. Each blocker has a `kind`, a `message`, and, when relevant, the `items` it names and the `people` whose action clears it. Gates that Flow cannot judge yet, such as a scan that is still running, appear in `unknown` with a `reason`. `ready` is `true` only when both lists are empty.

The read enforces nothing. `POST /project/{projectId}/branch/{id}/merge` checks its own gates again when you merge.

## Manage shared saved views

[`GET /project/{projectId}/views/saved`](/api/endpoints/get-project-projectid-views-saved) lists the project's shared saved views in display order. A view's `id` is the `view_id` that sharing a view takes. Creating, updating, and deleting shared views requires Admin access, and changes apply to every project member.

- [`POST /project/{projectId}/views/saved`](/api/endpoints/post-project-projectid-views-saved) adds a view after the existing ones. Set its start type and nesting rules by data type ID, and optionally its table `columns`, `filters`, and `sort`. Flow checks each against the data model and refuses a filter that names an unknown field, option, or type without saving anything. An `id` that already belongs to a shared view returns `409`.
- [`PATCH /project/{projectId}/views/saved/{viewId}`](/api/endpoints/patch-project-projectid-views-saved-viewid) changes only the fields you send. `relationships`, `columns`, `filters`, and `sort` each replace that whole part of the view. Send `null` to clear columns, filters, or sort.
- [`POST`](/api/endpoints/post-project-projectid-views-saved-viewid-relationships) and [`DELETE /project/{projectId}/views/saved/{viewId}/relationships`](/api/endpoints/delete-project-projectid-views-saved-viewid-relationships) add or remove one nesting rule, identified by `parentType` and `childType`, and keep the view's other rules. Adding a rule the view already has with the same `direction` changes nothing, so a retry is safe. The same pair with another direction returns `409`.

Display options are edited in Flow.

## Import ReqIF documents

A ReqIF import runs as a job. Each step returns quickly. Poll [`GET /project/{projectId}/reqif-import/{jobId}`](/api/endpoints/get-project-projectid-reqif-import-jobid) for its `status`, `phase`, and progress.

1. [`POST /project/{projectId}/reqif-import/upload`](/api/endpoints/post-project-projectid-reqif-import-upload) with `file_name`, `size`, and `mime_type` creates the job. PUT the `.reqif` or `.reqifz` bytes to the returned `upload_url` with its `upload_headers`.
2. [`POST /project/{projectId}/reqif-import/{jobId}/parse`](/api/endpoints/post-project-projectid-reqif-import-jobid-parse) parses the archive. Once parsed, the job's `schema` describes the file's types and attributes for your mapping.
3. [`POST /project/{projectId}/reqif-import/{jobId}/preview`](/api/endpoints/post-project-projectid-reqif-import-jobid-preview) shows what a commit with your mapping `clauses` would write. It writes nothing.
4. [`POST /project/{projectId}/reqif-import/{jobId}/commit`](/api/endpoints/post-project-projectid-reqif-import-jobid-commit) with the same `clauses` and a `branch_name` writes the import onto a new branch. Poll the job for progress and its `branch_id`.

Send the preview the clauses in the order you will commit them. `base_branch_id` names the branch the import would start from (omit it or send `master` for Base), and that branch decides whether each row creates or updates an item. Set `clause_id` to one clause's `id` to get a page of its rows. Each row has the ReqIF `identifier`, its `id_value`, the `values` the commit would write, and an `outcome` of `created` or `updated`. Page with `offset` and `limit` (default 50, maximum 100) while `has_more` is `true`. Set `include_counts` to also get created and updated `counts` for every clause. When `counts_complete` is `false`, the counts stopped before the end of the document and are lower bounds. The preview returns `400` unless the job is parsed and waiting for your mapping (`status` `waiting`, `phase` `parsed`).

## Shared item paths

Shared access grants can include `upstream_context_path_entity_ids` when a share shows the path above its item. Individual context grants have `view_id: null` and `context_of_grant_ids`; clients reading grants must handle a nullable `view_id`. Use `PUT /shared-grants/project/{projectId}/{id}/upstream-context` to replace the path. See the [endpoint reference](/api/reference) for its request schema.
