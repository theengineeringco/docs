Dashboards show how close a branch is to what the team intends to build: how many items exist, how their values are distributed, how well they connect, and how that has changed over time. They read the live state of the current branch, so they are unavailable while you view a baseline or a review snapshot.

Editors create and change dashboards; read-only users can view them. External users cannot open dashboards.

## Create a dashboard

1. Select **Dashboard** in the navigation, then **New dashboard** in the sidebar.
2. Name it and select **Create dashboard**.
3. Optionally, pick a saved view in **Select a view** to scope the dashboard to that view's types and filters.
4. Use **Filter** for conditions that apply to the whole dashboard. Add **Within items** to limit it to chosen items and everything below them.
5. Select **Add widget**, choose a **Widget type**, configure it, and check the preview. Optionally type a name in the box at the top; an unnamed widget is titled by what it shows.
6. Select **Add widget**.

Filter changes save as you make them. Drag a widget beside another or into its own row to arrange the dashboard; everyone sees the same layout.

You can also ask the Flow agent to build or edit a dashboard in chat. It works from the same project data and returns a link to the result.

| Widget type | Shows |
| --- | --- |
| Value block | The number of items, filled values, or percent filled, or the sum, average, minimum, or maximum of a number property |
| Property summary | How a property's values are distributed, as a donut, bar chart, stacked bar, or histogram, or how they changed over time |
| Link coverage | How many items of one type link to another type in the direction you choose, as a coverage donut or a percentage |
| AI summary | A generated reading of the dashboard from your prompt. Available when AI is on |

A widget's own **Filter** narrows that widget only. Link coverage counts links, not results: a test case linked to a system does not mean the test passed.

Select a chart segment to list the items behind it. When the dashboard has a saved view, **Open in table** opens those items in that view, keeping its filters. An AI summary shows its last result and when it was generated; select the refresh icon beside its title to update it, and check it against the widgets it describes before you share it.

## Read historical charts

A property summary can show history. Choose a historical chart (**Line**, **Multi-line**, **Stacked area**, **Bars**, or **Stacked bars**), set the date range and interval, and optionally add **Milestones** to mark dates such as a design review.

<VisualPlaceholder kind="Screenshot" title="A historical chart">
  A Property summary set to a Line chart of test status over 90 days with two milestones marked, and the "Not filtered by this dashboard" notice on the card.
</VisualPlaceholder>

Historical charts ignore the dashboard's filter and the saved view's filters, and the card says so. A widget filter blocks historical charts; remove it to choose one. **Within items** still applies, using today's hierarchy, so moving or deleting items also changes past buckets. Account for both before you compare a trend with a filtered current count. To see what changed and who changed it, use [Tracing history](/branching/tracing-history).
